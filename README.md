# COTA — 실시간 트레이딩 시그널

비트겟 USDT-M **코인 선물**을 실시간으로 스캔해 고승률 셋업만 골라 주는 모바일 우선 스캐너입니다.
토스/토스증권 스타일의 라이트 UI, 전면 한글 라벨, 종목별 가격 가독성, **연결된 비트겟 실계좌 잔고 기준** COTA 추천 레버리지를 제공합니다.

## 주요 기능

- **🔗 실계좌 잔고 기준 통합 + 주문 오류 자동 복구(v1.5.5)** — 첫 실행에서 받던 **수동 시드 입력을 없앴습니다**.
  모든 시그널·주문 계산(주문 수량·필요 증거금·예상 손익·누적 손익·포지션 사이징)이 **비트겟 자동매매에 연결한
  실계좌의 실시간 잔고(총 자산 equity)** 를 기준으로 돌아갑니다.
  - **시드 입력 제거**: 온보딩은 매매 성향(보수적/공격적)만 받고, 설정 탭의 `내 시드` 는 `계좌 잔고 · 가용` 표시로 바뀌었습니다.
  - **계좌 미연결 처리**: 카드의 콕핏은 숫자를 지어내지 않고 `실계좌 미연결` + `비트겟 자동매매에 계좌를 연결하면 실시간
    잔고 기준으로 계산됩니다` 안내와 **계좌 연결 버튼**을 보여줍니다(누르면 메뉴 → 자동매매 화면). 원클릭 주문·수량 복사도 숨깁니다.
  - **앱 수준 잔고 갱신**: 자동매매 화면을 닫고 스캐너에 머물러도 앱 시작·포그라운드 복귀·60초 주기로 잔고를 다시 읽어
    카드 수량이 항상 최신 잔고로 계산됩니다(자동매매 화면이 열려 있으면 12초).
  - **가용 잔고 캡**: 필요 증거금이 가용 잔고의 **95%** 를 넘으면 수량을 줄입니다(이미 잡힌 증거금·미실현 손실로 주문이
    거절되는 경우 방지). 네이티브 서비스도 주문 직전에 같은 식으로 수량을 다시 계산해, 앱을 닫아 둔 사이 낡은 수량이 나가지 않습니다.
  - **주문 오류 전수 한글화 + 자동 복구**: 거래소가 영문 코드만 돌려줘도 화면·로그·알림에 **한글 사유**가 먼저 남습니다
    (`45115 호가 단위` · `40774 포지션 모드(단방향/양방향)` · `40762/43006 최소 수량` · `43012/40754 증거금 부족` ·
    `40084/40085 계정 모드` · `40014/40018 키 권한` 등 70여 개 코드 + 원문 메시지 규칙). 실패하면 **사용자에게 묻지 않고**
    호가·계약 단위 재조회, 포지션 모드 반전(단방향↔양방향), 가용 95% 수량 축소, TP/SL 안전 여유 보정, 계정 모드 전환,
    일시 오류 재시도를 최대 2회 스스로 수행하고 `자동 보정: …` 을 로그에 남깁니다. 상장폐지·Demo 미지원 종목은
    **오늘 제외 목록**에 넣어 같은 실패를 반복하지 않습니다.
  - 검증: `check:cockpit` 58건 · `check:autotrade` 252건 · `autotrade-e2e` 119건(계좌 미연결→연결, 잔고 변경 반영,
    한글 오류·자동 보정 로그) · `features-check` 57건 · `toss-ui-check` 60건 · `journal-e2e` 44건 전수 통과.

- **🛡 SL 전 스마트 조기 손절(v1.5.4)** — 손절가까지 기다리지 않고, **진입 근거가 무너졌다고 판단되면 먼저 청산**합니다.
  - 청산 조건은 세 가지뿐입니다: **① 반대 방향 시그널**(포지션을 연 뒤 같은 종목에 반대 시그널이 새로 포착) ·
    **② 추세 구조 이탈**(마지막으로 마감된 15분봉이 반대쪽 장대봉으로 EMA9·진입가를 함께 이탈) · **③ 본절 보호**(+0.8R 이상 갔다가 본절 부근 복귀).
  - 휩쏘 방지: 진입 후 **2분 보호** · **마감된 캔들만** 판단(진행 중 봉의 꼬리 무시) · 평균 몸통 1.3배·가격 대비 0.15% 이상 장대봉 요구 ·
    손절가 −0.95R 이내는 거래소 SL에 맡김 · 같은 종목 5분 쿨다운 · 이미 +0.3R 이상 이익인 포지션은 반대 시그널로 자르지 않음.
  - 설정 `② 리스크 · 안전장치 → 조기 손절 보호`(기본 **ON**)에서 끌 수 있고, 실행되면 로그·알림에

- **🔓 1일 손실 한도 초기화 + 실시간 잔고(v1.5.4)** — 자동매매가 1일 손실 한도에 닿아 멈춘 뒤에도
  `🔓 손실한도 초기화` 버튼 한 번으로 **지금 계좌 잔고를 오늘의 기준선으로 다시 잡고** 바로 다시 켤 수 있습니다.
  - 초기화는 확인 모달(`현재 잔고 기준으로 오늘 손실 한도를 초기화할까요?`)을 거치고, 네이티브가 **계좌를 새로 조회**해
    기준선을 저장합니다(웹이 들고 있던 옛 기준선을 쓰지 않음). 그래서 초기화 직후 켜도 다시 잠기지 않습니다.
    초기화 직후 웹 기준선도 네이티브 값으로 맞추고, 결과는 로그·토스트로 남깁니다.
  - 같은 시그널 중복 진입 기록은 지우지 않습니다 — 기준선만 새로 잡고, 수량이 겹치는 위험은 그대로 막습니다.
  - 자동매매 화면이 열려 있는 동안 **12초마다** 총 자산·가용 잔고·미실현 손익·포지션을 자동 갱신하고
    `● 실시간 · 방금 전`(또는 `HH:MM:SS`)으로 마지막 갱신을 표시합니다. 탭을 벗어나거나 앱이 뒷전이면 interval을 정리하고,
    요청이 겹치면 건너뛰어 429(레이트리밋)를 피합니다. 백그라운드 서비스도 주기마다 잔고·가용·미실현·일일 손익을 저장해
    앱을 다시 열었을 때 최신 상태가 바로 보입니다.
  - 검증: `check:autotrade` 233/233(초기화·갱신·조기 손절 37건 추가) · `autotrade-e2e` 100/100
    (잠금 → 초기화 → 재가동, 12초 갱신, 화면 이탈 정리, 조기 손절 토글·로그).

- **🎯 호가 단위(45115) 수리(v1.5.2)** — 실기기 모의투자 테스트에서 모든 종목 주문이
  `45115 The price you enter should be a multiple of 0.01` 로 거절되던 문제를 고쳤습니다.
  - 원인: 감시 서비스가 `targets`/`stop` 숫자를 `%.8f` 로 다시 문자열화해 **호가 단위의 배수가 아닌 소수 꼬리**(예: `91234.567`)를
    TP/SL 로 보냈습니다. BTC는 `0.1`, ETH·BNB·MSTR은 `0.01` 배수여야 합니다.
  - 수리: 계약의 `pricePlace`(소수 자리)와 **`priceEndStep`**(스텝, `tick = step × 10^-pricePlace`)를 함께 읽어
    `roundToTick` 으로 호가 배수 문자열을 만듭니다(웹 `src/lib/autotrade.ts` · 네이티브 `BitgetApi.java` 동일 알고리즘).
    웹이 감시 항목에 `pricePlace`·`priceEndStep`·`tpStr`·`slStr` 를 실어 보내고, 네이티브는 **그 문자열을 손대지 않고** 주문에 씁니다.
  - 안전망: 그래도 `45115` 가 오면 네이티브가 공개 계약 API에서 호가를 읽어 TP/SL·지정가를 다시 맞춰 **한 번 재시도**합니다.
  - 회귀 검증: `check:autotrade` 에 BTC(0.1)·ETH/BNB/MSTR(0.01)·`priceEndStep=5`(0.0005) 케이스 추가.

- **🔗 비트겟 계정 자동 감지(v1.5.1)** — 통합 거래 계정(UTA, v3)과 클래식 계정(v2)을 **앱이 스스로 판별**해
  같은 화면·같은 버튼으로 둘 다 연결합니다. `GET /api/v3/account/settings`가 `00000`이면 통합계정,
  `40084`면 클래식이며, v2 호출이 `40085`를 돌려주면 즉시 v3로 전환해 **같은 요청을 한 번 더** 보냅니다.
  잔고(`/api/v3/account/assets`)·포지션(`/api/v3/position/current-position`)·레버리지(`/api/v3/account/set-leverage`)·
  주문(`/api/v3/trade/place-order`, `qty`·`posSide`·`takeProfit`/`stopLoss`)까지 두 계정 모두 동작하고,
  연결 화면에 `통합계정(UTA)` / `클래식 계정`이 표시됩니다.
  계정 안내: 통합계정 API는 키에 **UTA 거래(UTA trade)** 와 **UTA 계정 관리(UTA mgt, 읽기)** 권한이 필요합니다(`40014`).
- **🤖 비트겟 자동매매(v1.5.0)** — `메뉴 → 🤖 비트겟 자동매매`.
  - v1.5.1에서 `Passphrase: —` 로 보이던 저장 상태 표시를 수리했습니다(Key·Secret·Passphrase 저장 여부를 그대로 전달).
  - **네이티브 Private API 브리지**: 웹뷰 CORS를 우회해 안드로이드에서 비트겟 v2를 직접 호출합니다.
    서명은 `Base64(HMAC-SHA256(secret, timestamp+METHOD+requestPath+body))` + `ACCESS-KEY/SIGN/TIMESTAMP/PASSPHRASE`,
    모의투자는 `paptrading: 1`. **API 키는 기기 안(SharedPreferences)에만 저장**되고 Secret은 웹뷰로 내려오지 않습니다(화면엔 마스킹).
  - **24시간 감시**: 자동매매를 켜면 포그라운드 서비스가 상단 고정 알림(`COTA 자동매매 · 모의투자/실거래`)과 함께
    웹 엔진이 넘긴 감시 목록(진입가·손절가·목표가·수량·만료)의 **진입가 터치 · 손절 이탈 · 유효시간**을 주기(기본 60초)로 확인하고,
    통과하면 **레버리지 설정 → 시장가 주문 + TP/SL 동시 설정**까지 자동으로 넣습니다.
  - **안전장치**: 기본값 `OFF + 모의투자` · 1회 리스크(0.5~50%) · 최대 동시 포지션(기본 2) · **1일 손실 한도**(기본 4.5%, 0=끄기, 최대 100%)
    · 허용 종목(**전체 코인** 기본 — 주식선물·금·지수 제외 / 메이저 4종 / 주식선물 포함) · 최소 승률·손익비 · 레버리지 상한 · **중복 진입 방지**(시그널 키) · 긴급 `⏹ 즉시 중지`.
    한도에 닿으면 그날 자동 진입을 스스로 멈추고 알립니다. 1회 리스크 10% 이상은 `⚠️ 고위험 설정` 경고를 띄웁니다.
  - **시그널 카드 `⚡ 원클릭 주문`**: 카드에서 바로 모의/실거래 주문(수량은 시드×리스크%÷손절거리, 거래소 수량 단위로 내림).
  - 브라우저(웹 배포본)에서는 같은 규칙으로 **모의 시뮬레이션**만 돌려 어떤 시그널이 왜 통과/거부되는지 로그로 확인합니다(실제 주문·키 저장 불가).

- **HTF 추세 동조** — 1H 신호는 4H EMA50에 해당하는 EMA200 추세 방향에서만 냅니다. 추세를 거스르는
  역추세 셋업은 시그널에서 제외합니다.
- **정밀 타점 · 타이트 손절** — 손절은 직전 스윙·오더블록·FVG 경계, 신호 캔들 극값에 최소 버퍼만 붙여 붙이고,
  진입가 대비 손절폭 상한(**1H 3.5% · 4H 4.5%**, 하한 0.3%)을 넘는 시그널은 만들지 않습니다(목표가 ≤ 0 원천 차단).
- **비트겟 앱 바로가기** — 카드·공유 모달의 `비트겟 거래`는 안드로이드 APK에서 **비트겟 앱**으로 바로 열립니다
  (앱 링크 → 커스텀 딥링크 → 비트겟 앱 실행 → 미설치 시에만 브라우저).
- **카드** — `롱 · 매수 / 숏 · 매도`, `진입가 · 목표가 · 본전(EQ) · 손절가`, `손익비 1 : n`, `최근 승률`,
  천단위 콤마 가격, 목표·진입·손절 가격 라벨이 붙은 미니 캔들 차트, 진행률, `발송 11. 21. 09:00` 시그널 발송 시각.
- **실전 주문 콕핏** — 카드마다 **내 시드·리스크 기준 주문 수량**을 자동 계산합니다.
  - `수량 = (시드 × 리스크%) ÷ |진입가 − 손절가|` → `주문 수량 · 필요 증거금 · 손절 도달 시 · 목표 도달 시` 4칸
  - 기본 리스크는 성향별 **보수적 1.5% · 공격적 3%**, 설정 `💼 내 투자 프로필 → 실전 주문 리스크`에서 1/1.5/2/3/5%로 변경
  - 비트겟 계약 정보(`minTradeNum` · `volumePlace` · `minTradeUSDT`)를 받아 **주문 가능한 수량으로 내림**하고,
    최소 수량·최소 금액 미만이면 경고합니다(내림이라 손실은 계획을 넘지 않음)
  - `진입가` · `수량` 원클릭 복사 → 비트겟 앱 주문 화면에 그대로 붙여넣기
- **미니 캔들 차트 가격 라벨** — 실제 스캔 캔들 위에 목표가(빨강)·진입가(회색)·손절가(파랑) 점선과
  우측 가격 라벨을 함께 그립니다. 라벨이 겹치면 자동으로 위아래로 벌려 읽히게 합니다.
- **실시간 수익률** — 진행 중 시그널은 `현재 수익률 (진입가 기준)`으로 진입가 대비 현재가 변동률 × 레버리지를
  보여 주고, 내 시드 기준 `평가손익 +$321 / -$157`도 함께 표시합니다. 목표·손절 시나리오는
  실전 주문 콕핏의 `목표 도달 시 / 손절 도달 시`로 현재 손익과 섞이지 않게 구분합니다.
- **코인 로고** — 카드·공유 카드에 실제 코인 로고를 표시합니다. `1000PEPE` 같은 단위 파생 심볼은 원 코인(PEPE)
  로고로 맞추고, 로고가 없는 신규 밈코인·주식선물은 토스 스타일 글자 아바타로 깔끔하게 폴백합니다(깨진 이미지 0건).

- **비트겟 바로가기** — 카드의 `비트겟 바로가기 ↗` 버튼과 공유 카드 모달의 `비트겟 거래 ↗` 버튼이

  엽니다. 카드 본문 탭(공유 카드 모달)과 분리되어 있어 시그널을 보다가 바로 거래 화면으로 넘어갈 수 있습니다.
- **COTA 추천 레버리지** — 손절 폭·최근 승률·손익비로 시그널마다 배율을 계산합니다.
  - 보수적 매매: **2x ~ 5x** (손절 시 시드 손실을 12% 안쪽으로 억제)
  - 공격적 매매: **10x ~ 25x** (`floor(80 / 손절폭)` 안전 마진을 넘지 않음)
  - 카드에 `COTA 추천 Nx` 배지 + 내 시드 기준 **예상 수익(+)·손절 손실(-)** 표시
  - 레버리지 선택: `COTA 추천`(기본) 또는 `5x · 10x · 20x · 50x` 고정

  `localStorage('cota.profile.v1')`에 저장합니다. 설정 탭 `💼 내 투자 프로필`에서 언제든 다시 설정할 수 있습니다.

  (tickers의 `holdingAmount` = 미결제약정 수량 → USD 환산. OI 과거 시계열 API가 없어 변동률은 COTA가 관측한 직전 기록 대비)
- 업비트 `GET /v1/ticker|/v1/market/all` · 빗썸 `GET /public/ticker/ALL_KRW` · 환율 `open.er-api.com` ·
  공포·탐욕 `api.alternative.me/fng` — 모두 브라우저 CORS 통과를 헤드리스 Chromium으로 확인한 엔드포인트입니다.
- 1H/4H 200봉 실데이터를 최근 60봉 기준으로 백테스트해 승률·손익비 미달 전략은 즉시 교체합니다.
- 매매법 자체는 `npm run bench:strategies` 로 실제 비트겟 60개 마켓 500봉을 전수 백테스트해 채택/제거합니다.

## 주의

COTA는 비트겟 공개 시세를 계산해 과거 통계를 보여주는 **정보 도구**입니다. 투자 권유가 아니며,
표시된 승률·수익률은 과거 데이터 기준으로 미래 성과를 보장하지 않습니다. 레버리지 거래는 원금 전액을
잃을 수 있습니다. 카드의 주문 수량·예상 손익은 연결된 실계좌 잔고(총 자산)와 1회 리스크 %로 계산한 계획값이며,
급격한 변동·슬리피지·펀딩비로 실제 결과는 달라질 수 있습니다.
